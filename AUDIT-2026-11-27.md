## 2. Temuan

### CRITICAL

**C1. Path traversal di dashboard → kebocoran `.env` (kredensial penuh)**
- Lokasi: `dashboard.py:141` — `file_path = STATIC_DIR / self.path[len("/static/"):]` tanpa normalisasi/containment.
- Bukti (permintaan HTTP mentah ke `127.0.0.1:8060`):
  - `GET /static/../README.md` → `200`, 47500 byte (isi README)
  - `GET /static/../../RSI-Binance/.env` → `200`, **2991 byte** (BINANCE_API_KEY, BINANCE_API_SECRET, TELEGRAM_BOT_TOKEN)
  - `GET /static/../../../../etc/passwd` → `200`, 2159 byte
- Catatan: `curl` menormalkan `..` sehingga tampak 404; klien mentah berhasil.
- Dampak: bind `127.0.0.1` membatasi ke host, tetapi README mendokumentasikan opsi bind LAN (`DASHBOARD_HOST`) → siapa pun di LAN bisa mengambil API key. Juga setiap proses/user lokal di VPS.
- Perbaikan: resolve + containment check (`candidate.resolve().is_relative_to(STATIC_DIR.resolve())`), tolak `..`, dan tambahkan tes regresi.

### HIGH

**H1. Dashboard membaca state yang salah (dry) saat bot menulis state testnet**
- `deploy/rsi-dashboard.service` + unit aktif: `Environment=STATE_FILE=/home/ubuntu/RSI-Binance/state.json`.
- Bot sekarang `STATE_FILE=state.testnet.json`.
- Bukti: `/api/status` → `mode: dry`, umur snapshot 1654 detik; `state.testnet.json` mtime 21:48:41 sedangkan `state.json` 21:21:28.
- Dampak: operator melihat angka/posisi/mode dari lingkungan yang tidak berjalan. Kelas kesalahan yang paling berbahaya untuk bot trading.
- Perbaikan: set `STATE_FILE` unit ke file yang benar; idealnya dashboard membaca `.env` (atau `STATE_FILE` unit diturunkan dari `.env`) dan menampilkan peringatan keras bila umur snapshot > 2×`LOOP_SECONDS`.

**H2. Tidak ada kill switch / batas kerugian**
- Tidak ada max loss harian, max drawdown, atau max exposure selain `POSITION_PCT`, `MAX_OPEN_POSITIONS`, `MAX_ENTRIES_PER_WINDOW`, `COOLDOWN`, `LOCKOUT`.
- Untuk TESTNET dapat diterima; untuk LIVE ini gap terbesar: rangkaian SL berturut-turut hanya dibatasi waktu (cooldown 120 menit), bukan nominal.

### MEDIUM

**M1. Guard histori minimum 32 candle terlalu rendah untuk RSI Wilder**
- `bot.py:700` — `len(candles) < period + arm + 2` = 32.
- Galat RSI hingga 14.08 poin pada 32 candle (tabel di atas). `KLINE_LIMIT=1000` membuat ini tidak muncul pada pair lama, tetapi pair baru listing (32–100 jam) akan menghasilkan sinyal dari RSI yang belum konvergen.
- Perbaikan: naikkan ambang ke ~200 candle (atau `period*14`).

**M2. `poll_oco` menganggap "ada leg terbuka" = aktif → risiko oversell saat fill parsial**
- `bot.py:364-388`: bila salah satu leg masih di `fetch_open_orders`, langsung `return "active"`.
- Semantik OCO Binance: fill **parsial** pada satu leg tidak memperkecil leg lainnya. Jadi TP terisi 40% sementara leg SL tetap berkuantitas penuh → SL dapat menjual lebih banyak daripada sisa posisi.
- Bot tidak membandingkan kuantitas leg dengan `pos["qty"]`.
- Perbaikan: pada setiap poll, baca `amount`/`filled` kedua leg dan bandingkan dengan qty posisi; bila leg > posisi → fail-closed ke `reconciliation`.

**M3. State `reconciliation` tidak punya jalur pemulihan, dan README tidak memuat prosedurnya**
- `reconciliation_required` hanya dilepas di `arm_oco` sukses (`bot.py:620-621`) dan `gone_confirmed` (`569`). Tidak ada perintah/flag pemulihan.
- README menjelaskan *mengapa* fail-closed tetapi tidak menyebut field mana yang harus dikoreksi. Operator akan buntu saat kejadian pertama.
- Perbaikan: dokumentasikan resep per kasus (`position`, `pending_order`, `oco`, `oco_pending`, `reconciliation_required`) + contoh potongan JSON sebelum/sesudah.

**M4. Backtest tidak memodelkan slippage entry**
- `backtest.py:282` entry di `sub[i][4]` tanpa slip; `--slip` hanya dipakai untuk SL (`236`).
- Bot memakai market order (`create_market_buy_order_with_cost`) → realistis ada slip entry. Hasil backtest optimistis ~`--slip` per trade.

**M5. Write amplification state**
- `run()` → `persist("loop")` setiap `LOOP_SECONDS=5` → 17.280 tulis/hari × ~15 KB ≈ **260 MB/hari** tertulis (meski disk hanya menyimpan 15 KB). Pada eMMC/SD VPS ini memperpendek umur disk.
- Perbaikan: tandai state "dirty" dan tulis hanya saat berubah, atau minimal tiap 60 detik.

**M6. Dua definisi "equity" yang berbeda**
- Sizing: `bot.py:781-786` → `quote_free + Σ posisi terpantau` = 182.067 USDT → order 54.620.
- Dashboard: `bot.py:888-904` → seluruh akun MTM = 368.273 USDT (termasuk saldo drip ETH/BTC testnet).
- Akibat: `POSITION_PCT=30` tidak berarti 30% dari angka yang ditampilkan dashboard.

**M7. Dependensi tidak dipin**
- `requirements.txt`: `ccxt>=4.3.0`, tanpa batas atas/lock. ccxt merilis perubahan perilaku pada rilis minor. Tidak reproducible.

## 3. Yang sudah baik (diverifikasi, bukan klaim)

- **Look-ahead**: `prev`, arming lookback, dan basis Wilder selalu dari candle tertutup di bot dan backtest (paritas 0.0). TR candle berjalan hanya masuk lewat bobot 1/14.
- **Fail-closed**: pending order/OCO ambigu → pair dibekukan; tidak ada retry agresif yang bisa menduplikasi order.
- **Credential DRY RUN**: `exchange_credentials` mengembalikan `None` saat `dry_run` → `load_markets` tidak menyentuh endpoint signed.
- **Mode guard**: `new_state` menolak state beda mode (terbukti saat switch ke testnet).
- **Idempotensi tulis state**: tulis ke `.tmp` + `os.replace` + `chmod 0600` sebelum replace.
- **Notifikasi**: `notify` sebelum `save` saat shutdown; alert kegagalan save dibatasi satu per rentetan (`==` ambang).
- **Rate limit**: deteksi 418/429 + `Retry-After` → pause global, tanpa retry agresif.
- **Presisi order**: `cost_to_precision`, `amount_to_precision`, `price_to_precision` dipakai untuk buy/sell/OCO.
- **Fee accounting**: konsisten entry (base) dan exit (quote); cocok dengan rumus backtest sampai 1e-12.
- **Kebersihan git**: 18 file tracked, tidak ada `.env`/state/log di histori, token tidak ada di file tracked, `.gitignore` mencakup `state*.json*`.
